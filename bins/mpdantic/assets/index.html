The .mpdignore of this folder
The file as it is, one pattern per line; edit it here: type a line, remove one, tick a suggestion above. An empty field removes the file. Preview shows the lines added, removed and kept before anything is written, and every write can be undone from the Written tab. A line in force from a folder above is edited in that folder: the names under "Lines in force" open it.

Repair tags in this folder
The audio files of the folder in hand, not the folders under it. The album artist and the date written where MPD reads them, text that is UTF-8 read as Latin-1 decoded, a tag given twice kept once, an ID3v2 tag from ID3v1, and the Album, Album artist and Date every file gets where the files disagree. Each file is shown with its changes before anything is written. DSF and DFF files are read, not written.
Edit tags file by file
Every audio file of the folder in hand as a grid, one column per field MPD reads. Type in a cell, or set a column for every file at once; an empty cell removes the key. Nothing leaves the page until Preview, which shows every change key by key; the write and the undo are the same as for the repairs.

The queue
What Volumio plays now, read from the player itself and checked here. An item whose file is gone can be taken out of the queue through Volumio's own queue, as its page would; that is live state, not a file, so there is no undo for it.

System This player, as one block for an issue: what it is, and how its library sits against MPD's output buffer. It names no share, path or credential, only counts.
The album query is measured on your say: MPD is asked for every song with every tag, as Volumio's album view asks, and the reply is counted as it streams, never kept; on a large library MPD works for a few seconds. Paste the block into an issue on GitHub (the About tab has the link).
