# Changelog

All notable changes to MPDantic. The format follows Keep a Changelog; the versions follow Semantic Versioning.

## [Unreleased]

### Added

- The buttons organised by role on every tab: a panel's head carries, on the right, the one read-only job over the folder or the library (the queue and the album query measurement moved there, each in a panel of its own); a block's buttons sit under its text on the left and change nothing (the Ignore tab's Preview moved under its field); a commit is green with a grey Cancel beside it; an undo is amber, at the end of its line.
- A Volumio tab: Volumio's own playlists, favourites, radio favourites, web radios and the queue it last saved, read as Volumio keeps them and each item checked against the library (found when MPD's decoders claim the file, a video container the ffmpeg decoder claims included, since Glass plays it; not found; a foreign path; a stream; another service; no uri; the same uri again; a file cut short with how many items could be read). A list simply messed up is repaired on the write path: an item whose file is gone found again by its name and folders or dropped, a uri in twice kept once, an item without a uri dropped, a cut file written back with what could be read; the undo puts the file back. The queue as it plays now is read from the player's own socket, checked by the core, and the items whose files are gone can be taken out through Volumio's own queue, which is live state with no undo.
- The `.mpdignore` of the folder in hand is edited by hand: the field holds the file as it is, a line typed is added, a line deleted is removed, an empty field removes the file; the preview says the lines added, removed and kept; the names under "Lines in force" open the folder whose file carries the line.
- The line offered for a file no decoder claims carries the suffix as written, since MPD matches case for case: a `COPYING.GPLv3` is offered as `*.GPLv3`, not `*.gplv3`, which would not keep it out; up to two names are shown under each suffix so an offer explains itself.
- The tag editor, file by file, on the Tags tab: the audio files of the folder in hand as a grid, one row per file and one column per field MPD reads (track, title, artist, album artist, album, date, and on a tick disc, genre, composer, comment), every cell editable, a column set for every file at once, an empty cell removing the key; one Preview showing every file's changes key by key, one Write through the same path as the repairs (lofty in place, the audio guard, the journal per key), the undo as for every tag write. MP4's track and disc numbers written as the binary pairs they are. The MPD view gains composer and comment.
- `THIRD-PARTY-NOTICES` in the zip: every licence the core's crates carry (Apache-2.0, MIT, BSD-3-Clause for encoding_rs, Unicode-3.0 for unicode-ident), each text once with the crates under it, made by cargo-about at every build from `about.toml` and `about.hbs`; a crate under a licence not accepted there fails the build.
- The player report, on a System tab before About: one block of text for an issue, with the player (model, memory, architecture, Volumio version), MPD's version and decoders, the library's size from MPD's `stats`, the shares counted by type and nothing else of them, the output buffer with the bounds the rule found, and, on a click, the album query measured: MPD asked for every song with every tag as Volumio's album view asks, the reply counted as it streams and never kept, with the time Volumio's backend would take to read it. Copy puts it on the clipboard; the issue template on GitHub asks for it. The shell writes its buffer plan beside the settings for the core (`buffer.json`); the core serves `GET /api/report` and `POST /api/report/measure`.

## [0.1.0] - 2026-11-10

The first test cut, published as a pre-release for testing on more players and more libraries before the plugin store. Every feature below has been driven on a Raspberry Pi 5 (Volumio 4.239, the 32-bit image) and an x86 player (Volumio 4.231). Every write is undoable from the Written tab.

### Added

- The skeleton: the core (`bins/mpdantic`, one static binary per architecture, starts and waits), the shell (`plugin/`, the settings page with the management port and a status button, the core's service), the workshop pass (`scripts/check.sh`), the cross builds and the plugin zip, CI and the signed release workflow. Nothing to use yet.
- The management pages, served by the core on a port of the player (6218): the library as MPD sees it, folder by folder from the roots, read one directory at a time in pages; the core's status. The settings page opens them inside Volumio's page or in a tab, with the address browsers reach the player by (found on the player, or set); the pages are announced on the network through Avahi as "MPDantic on <player>".
- The `.mpdignore` analysis of a folder, read-only: a job walks everything under it and reports what MPD's update would meet by class, the lines already in force from the root down, and the lines that would keep out the archives MPD opens, the video containers its ffmpeg decoder claims, the folders a NAS writes for itself and the sidecar files a desktop leaves, each with its reason, count and examples. The audio suffixes are the running MPD's own (`decoders`), kept per plugin: what its own audio plugins claim is music, what ffmpeg alone claims is a class of its own, with text, lyrics and subtitle files suggested as lines. A `.mpdignore` line like `#recycle` is shown as dead: a comment to MPD, with `[#]recycle` as the line that works. The matching is MPD's own `fnmatch`.
- A switch on the page for video in the library: as Glass says (in use when the Glass plugin is on the player), in use, or not wanted; with video in use, video containers are counted and never suggested. Kept by the core under `/data/INTERNAL/mpdantic`.
- The CUE check of a folder, read-only: every sheet read as MPD's parser reads it, its FILEs looked for beside it, and the findings in MPD's terms (the FILE type MPD drops, a FILE missing or in another case or with another suffix, a FILE no decoder claims, a foreign path, an unquoted name, a byte-order mark, an encoding that is not UTF-8, an index MPD cannot use, several FILEs, two sheets naming one file, a sheet beside its split tracks, an index past the file's length), with the tracks MPD would make.
- The output buffer: MPD's `max_output_buffer_size` sized to the player through Volumio's own MPD configuration hook, the line appended after the template's and taken by MPD 0.21.19 or later as the later value (the version read; nothing appended to an older one). The size is the smallest of what the backend's heap holds (the reply as one string and its objects, six times its size while read, two at once), what the player's memory holds beside Volumio, the kiosk, MPD and the core, and what the backend reads in two minutes with its quadratic client; never below Volumio's 80 MiB, never above 1 GiB; at the floor nothing is appended. A switch on the settings page, on by default, with the value this player gets and the bound that holds it; the status toast says it too. The hook is registered before Volumio writes `mpd.conf` at boot, removed when the plugin stops, and `mpd.conf` is rewritten with MPD restarted only when the line changes.
- The first tab is `Ignore`; the About page's tab bar carries `Playlists`.
- On the tags card, each of Album, Album artist and Date can be typed, beside the values the files carry, since those can all be wrong.
- An MP3 with a stray header before its first frame (one of 4352 bytes seen) is written as it is read: lofty checks a file's format again before it writes and looked only a kilobyte past junk where its reader looks as far as needed, so the file the check had read was refused with "failed to write to file"; the core now gives both the same reach, a megabyte. A write error from lofty is said with its causes ("failed to parse file: no format could be determined" under the line above), not the line alone.
- The core writes the library's files whoever owns them: music copied onto the player through Volumio's network share belongs to nobody, and the core, as the volumio user, was refused ("cannot write there: Permission denied"). Its unit now grants it `CAP_DAC_OVERRIDE`, `CAP_CHOWN` and `CAP_FOWNER` and nothing more; a file it rewrites whole keeps its owner and mode, a new file takes its folder's owner, and the tag writes were in place already. No root, no helper, no change to the files' ownership.
- The sudoers entry the installer writes is self-contained: `mount` and `umount` for the write on a share and `tee` and `rm` on the announcement file are listed beside the core's unit, no longer taken from Volumio's own rule for the volumio user. The README says what the install puts on the player.
- The import of a library playlist into Volumio's own playlists: an Import into Volumio button on every playlist with entries MPD can load; the core writes the JSON file Volumio itself writes under `/data/playlist/<name>` (one item per entry with the title, artist and album from the file's tags and the album art as Volumio asks for it; a stream as a web radio), the name the file's stem or one typed on the card; an entry MPD cannot find, a foreign path or a file no decoder claims is left out and said. The file shown whole as Volumio would keep it; one Write; the undo removes it or puts back the one it replaced; nothing sent to MPD. The core takes `--volumio-playlists DIR` (`/data/playlist` unless given).
- The playlist check and repair, on a Playlists tab: every m3u, m3u8, pls and xspf under the folder in hand read as MPD reads it and each entry resolved as `load` does; the findings (an entry not found, a foreign path, an entry no decoder claims, a byte-order mark, not UTF-8, a PLS MPD rejects, an m3u8 or xspf Volumio never plays, no entry); the repair on the write path: the entries MPD cannot find looked for under the folder in hand by the longest tail of their path and written relative to the playlist's folder, the mark removed, the text re-encoded, a PLS given its section and count, a `.m3u` written beside an m3u8 or an xspf. Everything else in the file as written; the undo as for the sheets.
- The tag edits, for the audio files of the folder in hand: the album artist and the date written under the key MPD reads beside the key it does not, text that is UTF-8 read as Latin-1 decoded back, a tag given twice kept as its first value, an ID3v2 tag from the ID3v1 fields, and the Album, Album artist and Date every file gets where the files disagree, picked from the values the files carry. Every file listed with its changes key by key; one Write; written through lofty, the audio untouched (the audio between the tags measured before, its length and its first and last 64 KiB, and checked after; a file with no audio between its tags is not written); the journal keeping each file's changes and the undo setting every key back. DSF and DFF are read, not written. The MP4 atoms beginning with the copyright sign are now named right in the check.
- The About page at `/about`, the last tab as on every page of the family: what MPDantic is with its repository, releases, changelog and issues; the evo framework it is part of; what it is built of (MPDantic, lofty, encoding_rs, Music Player Daemon as read and not shipped, Volumio) with each piece's licence; Ko-fi and GitHub Sponsors; each link with a QR code.
- The CUE repairs: a sheet with a finding its text answers has a Repair button; the core says which repairs the sheet allows and shows it as it would be: the byte-order mark removed, the text read as a code page chosen on the card (Windows-1252 unless chosen; UTF-16 by its mark) and written as UTF-8, a FILE type MPD drops rewritten to one it takes, a FILE name rewritten to the file beside the sheet (another case, another suffix, the end of a foreign path), an unquoted name quoted; the sheet removed where two sheets or a sheet and its split tracks double the album, never by default. Everything else in the sheet stays byte for byte. On the write path of the first write: one Write button, the journal keeping the sheet's bytes as they were, the undo byte for byte, MPD's update after.
- The page in tabs under the folder in hand: `Ignore` (`.mpdignore` at first), `CUE sheets`, `Tags`, `Written` (every write, with its undo); the tab opened last opens again, `?tab=` opens one by name. A Close button when the page is a window of its own; inside Volumio's own page its arrow leads back. On the `.mpdignore` tab every suffix in the tables has a tick, and the ticks fill one list of lines to write, edited freely.
- The first write: `.mpdignore` lines into the folder in hand, from the suggestions ticked and a line typed. The core prepares the file whole and the page shows it (the lines added, the lines already there, the lines refused: a line starting with a hash is a comment to MPD and is refused with the line that works); one Write button; the file checked to be what the preview read, written whole and moved into place; the batch journaled under `/data/INTERNAL/mpdantic/undo` with the file as it was; MPD told to update the folder. On a NAS share the folder in hand is mounted read-write for the write, as the volumio user through the system's own `mount` with the credentials from Volumio's share configuration in a file only root reads and removed right after, in the core's own mount namespace, and released after; Volumio's read-only mounts are never touched. Every write is listed on the page with an Undo that puts the file back when nothing else has changed it since. The core's unit no longer sets `NoNewPrivileges`, which would block the mount; the rest of its hardening stays.
- The tag check of a folder, read-only: every audio file read for its tags as written through lofty (Vorbis comments, ID3v2 and ID3v1, APE, MP4 atoms; DSF and DFF through the ID3 tag their header points at), MPD's own name tables applied, and the findings in MPD's terms: a folder whose files disagree on Album or AlbumArtist and so shows as several albums, a title, artist or album MPD cannot read, an album artist or a date under a name MPD does not read, track and disc numbers missing or not numbers, UTF-8 read as Latin-1, ID3v1 alone, a tag given twice, a placeholder, an embedded cue sheet beside an external one, a file that could not be read.
